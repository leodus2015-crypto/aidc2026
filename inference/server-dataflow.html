推理服务七阶段数据流

以下用同一台推理服务器（CPU + DDR + 本地 SSD + 8×NPU/HBM，PD分离：上排 4 卡 Prefill、下排 4 卡 Decode）从上到下串联七个阶段： 未启动 → 空载启动 → 加载模型 → Question 到达 → Prefill → Decode → Answer 返回。每节保留相同的服务器结构，只叠加本阶段的数据流高亮。 灰色表示空闲，彩色表示运行态或已有文件。

0

服务器未启动

整机处于空闲态：CPU、DDR、NPU、HBM 均未参与推理；本地 SSD 上可已挂载 OS、驱动、容器镜像与模型权重文件，但服务进程尚未拉起。

  1. CPU 空闲。 推理引擎主进程、调度器、Tokenizer 均未运行。
  2. DDR 空闲。 主存中无请求与 token 中转数据。
  3. SSD 已有文件。 OS、驱动、容器镜像与模型权重已挂载（蓝色），等待启动后加载至 HBM。
  4. NPU / HBM 空闲。 8 卡资源池尚未参与任何计算。
空闲态（灰色） SSD 已有文件（蓝色） NPU 运行态（绿色）
1

服务器启动（未加载模型）

推理服务进程已启动：CPU 中运行主进程，DDR 中驻留推理引擎主进程；8 张 NPU 已上电，容器镜像从本地 SSD 加载至各卡 HBM 底部（约 10%），尚无模型权重。

  1. 进程就绪。 CPU 运行主进程；DDR 驻留推理引擎主进程。
  2. 镜像入 HBM。 容器镜像已加载至各卡 HBM 底部（约 10%），模型权重仍在 SSD。
  3. 不可推理。 此时尚未加载模型权重，也未接受用户 Question。
2

加载模型（SSD → HBM）

CPU 从本地 SSD 读取模型权重，分发至 8 张 NPU 的 HBM（PD分离 · 各卡持有相应分片）。在已有容器镜像（约 10%）基础上，HBM 新增模型权重区域（约 15%），并预留 KV Cache 空间。

  1. 读盘。 CPU 从本地 SSD 读取模型权重（绿色标注）。
  2. 传输。 权重写入各 NPU HBM，叠加于已有容器镜像之上。
  3. 就绪。 模型权重常驻 HBM（约 15%），可接受推理请求。
3

Question 到达（CPU 侧）

用户 Question 经网络进入 CPU；分词后 token 序列写入 DDR，并送往 NPU 等待 Prefill。HBM 中容器镜像（约 10%）、模型权重（约 15%）已就绪，尚未开始 KV 计算。

  1. 网络接收。 Question 报文进入 CPU。
  2. 分词。 CPU 将文本转为 token ID 序列，写入 DDR。
  3. 送往 NPU。 token 序列经调度送入 NPU 资源池，等待 Prefill。
4

Prefill（读完整 Question，生成 KV Cache）

输入 token 经 H2D 进入上排 4 张 Prefill 卡的 HBM，在已有模型权重基础上一次性处理全部 prompt，写入 KV 区域并产出第一个 Answer token（TTFT）；下排 Decode 卡待命。

  1. 下发。 DDR 中的 token 序列进入 NPU HBM。
  2. Prefill 计算。 复用 HBM 中模型权重，创建 KV Cache。
  3. 首 token。 得到第一个输出 token，TTFT 结束。
5

Decode（逐 token 生成 Answer）

每轮 Decode 复用 HBM 中的模型权重与 KV Cache，追加新 K/V，采样得到一个 token；循环直至 EOS。PD分离 · 上排 Prefill / 下排 Decode 分工。

  1. 读 KV。 NPU 从 HBM 读取已有 KV Cache 与上一 token。
  2. Decode 一步。 复用权重，追加新 K/V，采样得到 1 个 token。
  3. 循环。 重复直至结束。
6

Answer 返回（CPU 侧）

完整 token 序列从 NPU HBM 回到 DDR；CPU 反分词为 Answer 文本，再经网络返回用户。

  1. 回传。 token 序列写入 DDR。
  2. 反分词。 CPU 转为 Answer 文本。
  3. 交付。 经网络返回用户。
七阶段串联： 未启动 → 空载启动 → 加载模型 → Question → 上排 Prefill（写 KV）→ 下排 Decode（逐 token）→ Answer。架构为 8 PD分离（4 Prefill + 4 Decode）。
