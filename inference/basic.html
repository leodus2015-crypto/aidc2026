推理原理：Prefill / Decode

大模型推理不是一次性写完整答案，而是先在 Prefill 阶段读完整 Prompt、生成 KV Cache，再在 Decode 阶段逐 token 生成答案。

一次完整推理请求

  1. 用户输入 Question (Prompt)。 例如：“What does DC stand for”
  2. Tokenizer 切分 token。 文本被转换成模型可处理的 token id。
  3. Prefill 阶段。 模型一次性处理所有输入 token，并为每层 Attention 生成 KV Cache。
  4. Decode 阶段。 模型复用 KV Cache，每轮只生成一个新 token。
  5. 直到 EOS。 新 token 不断追加到上下文，直到生成结束符或达到长度限制。

先记住一句话

Prefill 决定首 token 前的等待时间，Decode 决定后续 token 的生成速度；KV Cache 是二者之间传递上下文记忆的关键。

一张图看完整过程：Prefill 生成 KV Cache，Decode 逐步复用

图中三个关键指标

  1. TTFT。 从请求进入到第一个输出 token 出来的时间，主要覆盖 Prompt 处理和 Prefill。
  2. TPOT。 Decode 阶段每生成一个 token 的间隔，决定流式输出是否顺滑。
  3. KV Cache。 Prefill 生成历史 token 的 K/V，Decode 每轮读取并追加新的 K/V。

工程含义

长 Prompt 会拉长 Prefill 和 TTFT；长输出会占用更多 Decode 时间；并发请求多时，KV Cache 会快速消耗显存。 所以推理服务需要同时优化计算、显存和调度。
