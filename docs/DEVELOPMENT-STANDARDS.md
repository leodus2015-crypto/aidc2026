# AIDC 网站开发规范

本文是 AIDC 网站新增页面、整改页面、接口和数据库变更的唯一权威规范。面向开发者、评审者和 AI 编码工具。现有页面可能暂未全部满足本文要求；新增代码必须遵守，存量代码按治理计划逐步迁移。

规范用词：

- **必须**：合并前必须满足；例外需要在 PR 中说明原因、风险和移除期限。
- **应该**：默认采用；偏离时应给出技术理由。
- **可以**：按页面需要选择。

## 1. 基本原则

1. 每个页面只有一个正式入口；语言、主题、embed 状态通过参数和共享能力表达，不复制多套 HTML。
2. 页面负责展示和交互，公式放入可测试的纯函数，数据访问通过统一客户端，浏览器不得直连数据库。
3. 优先复用 `js/`、`css/`、`i18n/` 中的共享能力，不在页面内复制导航、主题、语言和 API 基础逻辑。
4. 所有功能必须有明确的正常、空数据、输入错误、接口失败和加载中状态。
5. 不以“视觉正常”代替正确性、安全性、可访问性和可回退性。
6. 不顺手格式化或重写无关页面；一个提交只处理一个可独立回退的目标。

## 2. 文件与命名

- HTML、JS、CSS 和数据文件使用小写 kebab-case；历史文件在整改时逐步迁移，不为统一命名破坏旧 URL。
- 页面 HTML 放在与当前导航层级匹配的位置；共享代码放在 `js/`、`css/`，文案放在 `i18n/`，静态数据放在 `data/`。
- 页面 ID 必须稳定，并与 `<body data-i18n-page="page-id">` 及 `i18n/page-id.{zh,en}.json` 对齐。
- 页面专属脚本命名为 `js/<page-id>-page.js`；跨页面能力使用清晰的领域名，禁止 `common2.js`、`utils-new.js` 一类名称。
- 旧 URL 下线时优先由 Nginx 301 跳转；不要长期保留只有跳转功能的 HTML 壳。

## 3. 页面骨架与共享能力

新页面必须具备：

- `<!doctype html>`、UTF-8、viewport、description、title、canonical。
- `<body data-i18n-page="...">`，并存在中英文 i18n 文件。
- 尽早加载 `js/aidc-theme.js`，避免主题闪烁。
- 需要站点控件时加载 `theme-switch.js`、`i18n.js`、`lang-switch.js` 和 `i18n-bootstrap.js`。
- 可嵌入页面加载 `embed-mode.js`、`css/embed.css`，并实际验证 `?embed=1`。
- 资源版本使用站点统一版本机制，不手工引入彼此不一致的版本号。

页面不得复制一份长期独立演进的站点导航。需要新导航项时，同时更新导航结构、两种语言和页面注册信息。

## 4. 功能与计算规则

- 公式、单位和取整规则必须在代码注释或相邻文档中说明来源和口径。
- 计算逻辑应该提取成无 DOM 依赖的纯函数，并为正常值、0、空值、负值、极大值和边界百分比编写测试。
- 输入必须在计算前转换和校验；错误应显示给用户，不得传播为 `NaN`、`Infinity`、空白或错误图表。
- 百分比组合、容量上限和总和约束必须显式校验，不能只依赖 HTML `min`/`max`。
- 动态结果应标明单位、时间范围、数据来源和更新时间；估算值必须标明“规划估算”或相应免责声明。
- API 或数据库不可用时，允许使用受版本控制的本地默认值；界面必须明确显示数据来源，不能静默伪装成云端数据。
- 页面初始化必须可重复执行；切换语言和主题不得重复绑定事件或重建无关状态。

## 5. UI 与响应式

- 使用 `css/theme.css` 的 `--aidc-*` 语义变量和既有组件样式；新页面壳不得散布裸色值。
- 品牌主色用于导航、主要动作和关键数据；危险、警告、成功状态使用一致的语义色，不只依靠颜色表达含义。
- 内容宽度、间距、圆角、边框和阴影应与现有主页面一致；同级控件不得随页面任意更换视觉语言。
- 桌面、平板和手机均不得产生非必要横向滚动。表格在窄屏下使用滚动容器或信息卡降级。
- 表单控件必须有可见 label、错误说明和焦点样式；占位符不能代替 label。
- 交互元素使用原生 `button`、`a`、`input` 等语义元素，不用普通 `div` 模拟。
- iframe 必须有可翻译的 `title`，容器应有合理最小高度，父子页面不得形成嵌套站点壳。
- 图表和 SVG 必须在两种主题下可读，并为关键结论提供文字或表格替代。

## 6. 动画规则

- 动画只用于解释状态变化、空间关系或操作反馈，不作为装饰性阻塞流程。
- 优先动画 `transform` 和 `opacity`；避免持续改变 width、height、top、left 造成布局抖动。
- 常规反馈建议 120–240ms，面板切换建议不超过 360ms；循环动画必须可停止且不得干扰阅读。
- 必须支持 `prefers-reduced-motion: reduce`：关闭循环、视差、大幅位移和平滑滚动，保留必要的即时状态反馈。
- 动画开始前和结束后都应保持内容可读；不得把关键信息仅放在 hover 或动画中。
- iframe 切主题、切语言时不得通过整页重载制造过渡效果。

## 7. 中英文与主题

- 中文与英文文案分别维护在 `i18n/<page-id>.zh.json` 和 `.en.json`，键结构必须一致。
- HTML 中保留可读的中文回退文案；禁止向用户显示 `nav.home` 一类键路径。
- 动态生成文本也必须走 i18n；不得只翻译静态 DOM。
- 数字、日期、单位和复数形式按当前 locale 格式化；专有名词保持团队词汇表一致。
- 语言由 `?lang=`、`AidcI18n` 和 `AidcLocaleBridge` 统一管理，iframe 必须跟随父页。
- Light/Dark 是同一页面的两种状态，不复制 HTML。切换主题必须同步 iframe，且不丢失输入和计算结果。
- 合并前必须验证：中文 Light、中文 Dark、英文 Light、英文 Dark。

## 8. 可访问性

- 页面必须支持键盘完成主流程；焦点顺序与视觉顺序一致。
- Tab、对话框、菜单等复合组件遵循对应 ARIA 模式，并维护 `aria-selected`、`aria-expanded`、`aria-hidden`。
- 图片有准确 `alt`；纯装饰图使用空 alt 或 `aria-hidden="true"`。
- 状态和校验错误使用可被辅助技术感知的文本；必要时使用 `aria-live`，避免滥用。
- 正文和控件满足合理颜色对比度；正文不因响应式缩放到难以阅读。
- 标题层级连续，每页有且只有一个主要 `h1`。

## 9. 前端数据访问

- 所有 HTTP 请求必须经过统一 API 客户端；页面脚本不得各自实现 base URL、超时、认证和错误解析。
- 请求必须设置有限超时；可取消的页面请求使用 `AbortController`。
- GET 可以按契约回退本地数据；写请求禁止“假成功”，失败必须保留用户输入并给出可操作提示。
- 管理凭据只允许由用户主动输入并存放于当前会话；不得写入源码、JSON、URL、localStorage、日志或分析事件。
- 不在浏览器中读取用于验证自身的密码、哈希或管理令牌。客户端隐藏按钮不属于安全控制。
- 渲染远端数据时使用 `textContent` 或经过审计的转义函数；不得把不可信字段直接拼入 `innerHTML`。

## 10. API 规则

- API 路径、请求、响应和错误必须有明确版本与契约；破坏性变更需提供迁移期。
- FastAPI 端点使用 Pydantic 请求/响应模型，不返回数据库原始行或 Python 异常文本。
- 错误响应应包含稳定错误码、面向用户的安全消息和请求 ID；详细异常只记录在服务端。
- 配置项按键声明读取权限、写入权限、schema 和本地回退策略；敏感配置永不通过公共 GET 返回。
- 写操作必须认证、限制请求体大小、校验 Content-Type，并采用版本号或等价的并发控制防止覆盖更新。
- CORS 使用明确来源列表；带凭据请求不得与通配来源组合。
- 管理和分析接口应配置速率限制、安全日志和失败告警。

## 11. 数据库规则

- 浏览器和静态页面不得直接访问数据库；数据库只允许 API、受控任务和迁移脚本访问。
- SQL 必须参数化；动态列名、排序和表名只能来自服务端白名单。
- 数据库账号遵循最小权限：运行账号无建库、改表权限，迁移账号独立保管。
- schema 变更通过有序迁移文件完成，禁止只修改 `schema.sql` 后直接在线上手工执行。
- 迁移必须说明前滚、回滚、兼容窗口、锁表风险和备份要求。
- 写操作使用明确事务边界；跨事务读取不得依赖未提交状态。
- 配置和关键业务数据保留版本、修改者、修改时间和必要审计记录。
- 日志与分析数据按最小化原则采集；IP、凭据和个人信息必须脱敏并设定保留周期。
- 备份必须定期验证恢复，而不只验证文件生成成功。

## 12. 安全规则

- 秘钥只通过环境变量或部署平台 Secret 注入；`.env`、生产数据和私钥不得提交。
- 禁止默认口令、前端硬编码口令、公开可读的解锁口令和将同一凭据同时用于 UI 解锁与服务端管理。
- 新增外部脚本、字体或接口前评估供应链、CSP、隐私和离线回退；优先使用本地固定版本资源。
- CSP 违规应先在 Report-Only 中清零，再转为强制策略；不得以长期保留 `unsafe-eval` 代替整改。
- 外部链接按场景设置 `rel="noopener noreferrer"`；跳转和资源 URL 不接受未经验证的用户输入。
- 任何安全例外必须记录责任人、原因和到期时间。

## 13. 性能与可靠性

- 非首屏 iframe、图片和大型资源使用延迟加载；首屏关键资源避免重复下载。
- 图片提供明确尺寸，避免布局偏移；大型 SVG、数据集和脚本应按页面拆分。
- 不在滚动、resize、pointermove 中执行无节流的重计算。
- 第三方 CDN 失败时，核心阅读内容仍应可访问；关键生产依赖应该本地化和固定版本。
- 主题、语言和 Tab 切换应保留页面状态，避免无必要的网络请求。

## 14. 测试与验收

每个变更批次至少执行：

```bash
python3 scripts/check-site.py
python3 -m pytest tests -q
```

涉及 UI、i18n、主题、计算器、iframe 或配置加载时，还必须按 `docs/TEST.md` 完成浏览器冒烟。

测试分层：

1. 静态检查：JSON、i18n、引用、页面注册、部署配置和敏感信息。
2. 单元测试：公式、验证器、API 权限、错误与回退。
3. 浏览器冒烟：主路径、四种语言/主题组合、移动端、embed、接口正常/故障。
4. 部署验证：关键 URL、静态资源、API 健康和回滚准备。

不得以跳过检查作为常规开发流程。确需跳过时，必须在提交或 PR 中记录原因并补测。

## 15. Git、评审与合并

- 开始工作前保持基线清晰；存量未提交变更必须先归档或明确隔离。
- 一个提交对应一个可说明、可测试、可回滚的目标；页面整改不混入全仓格式化。
- PR 必须说明目标、改动范围、数据/API 影响、截图或行为证据、测试结果、风险与回滚方式。
- PR 必须通过 GitHub Actions `CI` 工作流（`check-site.py` + `pytest`）。CI 不部署。正式上线只走本机 `scripts/deploy.sh`；GitHub 为开源归档，push 不得 rsync 覆盖腾讯云。
- 数据库迁移、认证、部署和公共导航变更需要更严格评审。
- 不直接覆盖他人未提交改动；冲突解决后重新运行完整检查。
- push、合并和部署是三个独立动作，分别获得授权并保留记录。

## 16. 新页面完成定义

新页面只有同时满足以下条件才可合并：

- 已登记页面 ID、入口、父子关系、资源和数据依赖。
- 页面骨架、导航、主题、i18n、embed 和错误状态符合本规范。
- 中文/英文 × Light/Dark 四态可用，移动端与键盘主路径可用。
- 公式和数据有来源、单位、校验、边界测试及失败回退。
- API/数据库访问经过统一客户端和服务端契约，无敏感数据泄露。
- 静态检查、单元测试和适用的浏览器冒烟全部通过。
- 文档、提交说明、风险和回滚方式完整。
